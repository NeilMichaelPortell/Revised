# 00 — Evidence and Artefact Map

Generated 2026-07-19 as the entry point into this write-up pack. Every other
file in `thesis_writeup/` cites a source CSV/report by path; this file maps
each *kind* of dissertation evidence to where it physically lives, so a
chapter section can always be traced back to a regenerable, hash-checked
artefact rather than a number typed into prose.

## How to use this pack

1. Start here to find which canonical path backs a given result area.
2. Open the matching `0N_CHAPTER_*` file for narrative-ready facts.
3. Cross-check any specific number against `08_CLAIM_EVIDENCE_MATRIX.csv`
   (claim -> exact source file/column) before quoting it in the dissertation.
4. Build the Excel workbook from `excel_source/*.csv` — those files are
   already clean, single-purpose exports of the canonical CSVs, safe to
   import directly as worksheets.
5. If a number looks surprising, re-derive it: `docs/final_audit/
   FROZEN_ARTIFACT_HASHES.csv` lets you confirm the underlying raw file is
   unchanged before trusting a downstream number.

## What changed in this pass (2026-07-19), in one paragraph

The previous comparison evaluator excluded non-committal/placeholder model
outputs from recall, F1 and class-level metrics entirely, which silently
rewarded refusing to answer. It has been corrected to classify every one of
the 120 scenarios into exactly one of five categories (valid_correct,
valid_incorrect, invalid, missing, fallback) and to fold invalid/missing/
fallback outputs into coverage-adjusted recall/specificity/F1 as failures.
The consistency evaluator's p-value display bug (`p = 0.000` instead of
`p < 0.001`) was fixed, and a hang caused by the evaluator shelling out to the
`ollama` CLI for version metadata was removed (evaluators must never invoke
Ollama). Indicator scoring was corrected to **exact** controlled-vocabulary-
token matching (case-fold + trim only; no substring, no underscore folding, no
synonym mapping) in the primary and OTRF evaluators. The OTRF external
evaluation is now **completed in strict mode**: all 18 raw source captures were
located in a local untracked OTRF clone and hash-verified (18/18 source +
18/18 neutral), the raw archives were removed from Git tracking and ignored,
and the evaluator ran clean without any override flag. See
`04_CHAPTER_4_EXTERNAL_VALIDATION_RESULTS.md`.
